- (decision) AD-1 Paradigm: hexagonal (ports and adapters) modular monolith. Projects Core (domain + use cases + ports, no ASP.NET, no provider SDK), Infrastructure (adapters), Api (minimal API + composition root). Deps: Api -> Infrastructure -> Core; Api -> Core. Alternatives weighed: layered N-tier (leaks EF/SDK types upward), Semantic Kernel plugins (heavy for a learner, hides the RAG steps), vertical slices (fine but weaker seam for provider swap). Prevents: business logic in endpoints, provider types leaking, untestable model calls.
- (decision) AD-2 Model access only through Microsoft.Extensions.AI abstractions (IChatClient, IEmbeddingGenerator<string,Embedding<float>>); they ARE the provider ports. Adapters: ollama (OllamaSharp) default, openai (Microsoft.Extensions.AI.OpenAI; also Azure OpenAI/OpenAI-compatible via endpoint). Chat and embedding provider chosen independently by config Providers:Chat / Providers:Embedding in the composition root only. Weighed: Semantic Kernel (more concepts, hides calls), raw provider SDK (teaches wire level but breaks FR-9 swap). Simon delegated (fast path). Anthropic adapter deferred.
- (decision) AD-3 Interview flow is a code-owned state machine in Core. The model only writes text or fills typed structured output; it never decides question count, follow-up cap (max 1 per Question), source mix (>=1 Resume-based and >=1 Question Bank when bank non-empty), or when the session ends. Prevents model drift making sessions endless or skipping the bank.
- (decision) AD-4 Session state is server-side in memory (ISessionStore, singleton, idle expiry). Holds Resume text, ResumeProfile, planned questions, transcript. Resume text held only there: never persisted, never logged, purged when session ends or expires. Transcript kept until the Coaching Report is delivered (so report Retry works), then session removed. Client holds only sessionId + rendered messages; reload = lost id = session over (matches UX). Weighed stateless (client resends resume+history: bigger payloads, resume in browser).
- (decision) AD-5 Turn commit protocol: answer is committed on receipt; bot reply is committed to transcript only when its stream completes; aborted/failed reply leaves the answer committed and no bot message; Retry is a separate endpoint that regenerates the reply for the last committed answer; Stop = client aborts fetch and the CancellationToken flows to the model call.
- (decision) AD-6 Streaming wire format: chat replies stream over POST as text/event-stream via TypedResults.ServerSentEvents; client reads with fetch + ReadableStream (EventSource is GET-only). Events: token (text delta), done, error(problem code). Everything else is plain JSON.
- (decision) AD-7 Question Bank persistence: single SQLite file via EF Core (Storage path config, default data/interview-prep.db, gitignored). Question row: id (long autoincrement), text, normalized_text (unique), reference_answer (nullable), embedding (float32 BLOB, nullable), embedding_profile (string provider:model:dims), created_at (UTC). Only IQuestionBank (Core port, single writer) mutates it. Weighed pgvector/Qdrant (extra server, not needed for hundreds of rows) and vector-store abstractions (hide the retrieval math Simon wants to learn).
- (decision) AD-8 Retrieval: brute-force cosine similarity over all embeddings loaded in memory, behind IQuestionRetriever port (top-k, excludes deleted + already-asked). Cache invalidated on every bank write. Only Question text is embedded (PRD: no tags, text alone); Reference Answers are never embedded and never in interview-turn prompts. Vectors valid only for the recorded embedding_profile.
- (decision) AD-9 Embedding profile reconciliation (FR-10): on startup and via POST /api/admin/re-embed, every row whose embedding_profile differs from the configured one is re-embedded; retrieval ignores rows with mismatched/null profile. No UI (UX: no Provider UI in v1).
- (decision) AD-10 Embedding provider quirks (e.g. nomic-embed-text needs search_document:/search_query: prefixes) are absorbed by an Infrastructure decorator on IEmbeddingGenerator; Core passes plain text plus an intent (document|query) via a Core IQuestionEmbedder wrapper. Prevents prefix logic leaking into Core or breaking swap.
- (decision) AD-11 Machine-consumed model output always uses typed structured output (IChatClient.GetResponseAsync<T>, T = Core records); never regex/parse prose. Deserialization failure: one retry, then typed provider error. Coaching Report is a typed record (summary, strengths[], weakSpots[], reviews[]); no numeric score; each strength/weak spot carries questionNo + short quote (FR-8).
- (decision) AD-12 Coaching context budget: coaching prompts contain at most ONE Reference Answer at a time. Report = one structured review call per answered Question (with its Reference Answer or the rubric) then one synthesis call over the per-Question verdicts. Report endpoint is non-streaming JSON.
- (decision) AD-13 Document ingestion: IDocumentTextExtractor port in Core; adapters in Infrastructure (DOCX: DocumentFormat.OpenXml; PDF: PdfPig; TXT: UTF-8). Type detected by content signature, not client content-type or extension alone. Output is plain text, paragraphs separated by newline; zero text => unreadable-document error. Import parsing is a pure Core function on extracted text using a line-start Q<number>. pattern, ignoring text before Q1, answer = text up to next Question; parts that do not fit are reported as skipped with reason. No LLM extraction in v1.
- (assumption) Import dedupe (UX open Q3): a Question whose normalized text (trim, collapse whitespace, casefold) already exists is skipped and listed as Already in the Question Bank; unique index on normalized_text enforces it. Import and add are atomic: if embedding fails nothing is saved and the user gets a retryable error.
- (assumption) Max upload size 10 MB for Resume and import (UX open Q2), enforced server-side per endpoint, 413 with problem code file-too-large; configurable.
- (decision) AD-14 API conventions: REST JSON under /api, camelCase, ISO-8601 UTC, ids as JSON numbers (bank) or opaque strings (sessionId). Errors are RFC 9457 ProblemDetails with a stable machine type slug (provider-unavailable, unreadable-document, unsupported-file-type, file-too-large, session-not-found, invalid-request, embedding-out-of-date) that the frontend maps to UX copy; raw exception text never leaves the server.

All API calls via one src/api module using relative /api URLs; single hand-written src/api/types.ts mirrors backend DTOs. Dev: Vite proxies /api to Kestrel, so no CORS anywhere.
- (decision) AD-16 Secrets and exposure: API keys only via .NET user-secrets (dev) / env vars, bound with validated options (ValidateOnStart); no endpoint returns config; Kestrel binds loopback only in v1 because there is no auth and anyone can edit the shared bank. No Resume text, answers, or Reference Answers in logs.

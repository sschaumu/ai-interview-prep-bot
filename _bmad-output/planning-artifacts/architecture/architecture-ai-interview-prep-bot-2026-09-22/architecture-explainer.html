1. The big picture

Three programs run on your machine. The browser shows a React app. A C# web API does the thinking about what happens next. Ollama runs the language model. The API never lets the browser talk to the model directly, and that keeps any API keys out of the browser.

Inside the C# API the code is split into three projects, and the arrows only point one way:

Api  ──►  Infrastructure  ──►  Core
 └──────────────────────────►  Core

Core holds the rules (the interview state machine, the parser, the prompts) and the ports: interfaces that say "I need something that can chat" or "I need somewhere to store Questions". Infrastructure holds the adapters that plug real things into those ports: Ollama, OpenAI, SQLite, Word and PDF readers. Api is the thin HTTP layer that wires everything together. This pattern is called hexagonal architecture or ports and adapters.

Say it in one sentence: the interesting logic never knows which model or database it is using, so I can swap them by changing a setting.

2. RAG: how the bot finds Questions

RAG means retrieval-augmented generation: before the model writes anything, you retrieve relevant text from your own data and put it in the prompt. Here the data is the Question Bank. The trick that makes retrieval work is the embedding.

An embedding is a location for meaning

An embedding model turns a piece of text into a list of numbers (768 of them for nomic-embed-text). Think of it as coordinates on a map of meaning. Texts about similar things land near each other, even when they share no words. "How do you cancel a running task in C#?" ends up close to "Explain CancellationToken" and far from "Describe Azure Key Vault".

Two phases

"Closest" means cosine similarity

To compare two vectors you measure the angle between them. Cosine similarity gives 1 for the same direction, 0 for unrelated and negative for opposite. Your bank has 87 Questions today, so the API simply scores all of them in memory and keeps the top few. No vector database is needed at this size, and writing that loop yourself is the best way to learn what a vector database does for you at scale.

This uses simple word overlap, not a real embedding model, so it only catches shared words. A real model also catches shared meaning, which is the whole point of embeddings.

3. Swapping providers without touching code

Microsoft ships two small interfaces, IChatClient and IEmbeddingGenerator. Every provider library can produce one. Core only ever sees those interfaces, so it cannot tell whether Ollama or OpenAI is behind them.

The choice is made in one place, the API's startup code, by reading configuration. Chat and embeddings are chosen separately, so you could chat with a paid model while embedding locally.

// appsettings.json (default, free)
"Providers": {
  "Chat":      { "Type": "ollama", "Model": "gemma3:4b" },
  "Embedding": { "Type": "ollama", "Model": "nomic-embed-text" }
}

// switch chat to a paid model: change config, not code
"Chat": { "Type": "openai", "Model": "gpt-...", "ApiKey": "(from user-secrets)" }
Two catches to remember. First, changing the embedding provider makes every stored vector incompatible, so the app re-embeds the bank at startup. Second, the API key lives in .NET user-secrets on the server and never reaches the browser.
Say it in one sentence: the code depends on an interface, and a setting decides which real model is plugged in behind it.

4. One interview turn, end to end

  1. You type an answer in React and press Send. The app generates a turnId and POSTs it to /api/interview/sessions/{id}/turns.
  2. The API saves your answer, then Core's state machine decides the next step: a follow-up, the next Resume question, or the next Question Bank question.
  3. For a bank turn, Core embeds the interview context, scores the stored vectors and picks the best Question not yet asked.
  4. Core builds a prompt (system instructions, your Resume, that one Question, the last few exchanges) and asks the model to phrase it.
  5. The model's words stream back as small token events over server-sent events. React appends them to the chat bubble as they arrive.
  6. When the stream finishes, the API saves the bot's reply and sends a done event telling React the question number, its source and whether the interview is over.
What if I press Stop, or the model fails halfway?

Your answer is already saved and the bot's partial reply is not. Retry re-sends the same turnId, and the server replays the same decision instead of making a new one, so you never get a skipped or doubled question.

Why server-sent events and not WebSockets?

The text only flows one way, server to browser, and SSE is plain HTTP that ASP.NET Core 10 supports directly. Because the browser's EventSource can only send GET requests, the React app reads the stream with fetch instead.

5. Why code runs the interview, not the model

A small local model is good at wording a question and poor at bookkeeping. So a C# state machine owns the things that must be exactly right: about 10 questions, at most one follow-up each, at least one Resume question and one bank question, and when to stop. The model only writes text, or fills in a fixed shape (structured output) that the code can read safely.

The same idea applies to coaching. The report must be a typed object, and the code checks it: at least one strength, at least one weak spot, and every quote must really appear in your answer. If the model fails the check, the code asks again once, then reports an error instead of showing made-up feedback.

Say it in one sentence: the model writes the words and the code keeps the rules.

The API only listens on localhost and rejects requests from other websites, because there are no accounts. If you switch to a hosted provider, your Resume text is sent to that provider. That is your call, and it is documented, not blocked.

7. Explain-it-yourself checklist

These match the learning goal in the PRD (SM-2). Try answering out loud, then open the hint.

What is an embedding and why do similar Questions end up close together?

A model maps text to a list of numbers so that similar meaning gives similar numbers. Closeness is measured with cosine similarity.

Walk through what happens between importing a file and the bot asking one of its Questions.

Extract text, parse Q<n>. blocks, embed each Question's text, store row and vector, later embed the interview context, compare against all vectors, take the best unasked match, wrap it in a prompt.

Why can't I mix vectors from two different embedding models?

Each model has its own coordinate system, so distances between them are meaningless. That is why each row stores an embedding profile and the bank is re-embedded on change.

How does one config change move the bot from Ollama to OpenAI?

Core depends on IChatClient. At startup the composition root reads Providers:Chat:Type and builds the matching adapter.

How do a React component, its state and a backend call fit together?

The component holds messages in state. Sending calls a function in src/api, which does a fetch to /api/.... Each streamed token updates state, and React re-renders the bubble.

Which modern C# features show up, and why?

Records for DTOs and model output, nullable reference types, async streams (IAsyncEnumerable) for streaming, minimal APIs, dependency injection, and CancellationToken so Stop actually stops the model.
